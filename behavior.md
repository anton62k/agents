# Behavior

Shared behavior for every agent, from any working directory.

## Agent attribution

Do not add agent- or AI-identifying attribution, signatures, or promotional
boilerplate to commits, pull requests, issues, comments, release notes, or other
project artifacts. This includes `Co-authored-by` entries for an agent and text
such as "Generated with" or "Generated by". Add such disclosure only when the
user explicitly requests it or an applicable repository, organizational, legal,
or platform policy requires it. Preserve attribution to human contributors.

## Instruction structure

Keep this file small: shared principles and links with explicit loading conditions.
Put new topic-specific rules of comparable scope in separate Markdown files and
add a conditional link here. Load those files only when their topic applies;
do not copy their detailed rules into this file or load all linked files upfront.

## Project development

Before starting development that changes a repository, or managing development
worktrees, load `$HOME/.agents/rules/project-development.md`.
They cover project discovery, worktree consent and setup, ignored files,
dependencies, the local registry, and cleanup after merge.
Read-only exploration and general discussion do not require this file.

## Shared agent configuration

Before changing `$HOME/.agents` or its repository, load `$HOME/.agents/AGENTS.md`.
Ask the user before opening a pull request there, explain what it changes and why,
and never merge it without an explicit request. Keep project-specific content out
of it.

## Saved prompts and agent handoffs

When asked to prepare a prompt for another agent, or find, execute, resume, or
maintain a saved task, load `$HOME/.agents/rules/saved-prompts.md`.
The local store is `$HOME/.prompts`; users can identify tasks by description
without providing a path. Load these rules only for saved tasks and handoffs,
not for every ordinary use of the word "prompt".

## Code intelligence

When working in a source-code repository, answering structural code questions,
or creating and removing development worktrees, load
`$HOME/.agents/rules/codegraph-development.md`. They cover
automatic local indexing, agent usage, worktree-local indexes, freshness,
Git-ignore behavior, and cleanup. Do not load them for general discussion,
saved-prompt lookup, or work containing no supported source code.

## Isolated development sandboxes

Before starting repository development that executes the application or depends
on project runtimes, assess whether an isolated Docker Sandbox would materially
improve reproducibility, safety, or parallel operation. When it would help,
include it in the proposed development workflow with a short reason and load
`$HOME/.agents/rules/sandbox-development.md`.

Do not propose a sandbox for documentation, small static edits, or checks that
do not need an isolated runtime or stateful services. A sandbox is temporary
task infrastructure: remove it when it is no longer needed and always before
removing its worktree. Finish with an explicit sandbox outcome when one was used.

## Routing

Load provider-specific instructions only when the user explicitly asks to use
Grok, Codex, or Claude. Start with `$HOME/.agents/provider-routing.md`,
then open only the requested provider's guide:

- Codex: `$HOME/.agents/providers/codex.md`
- Claude Code: `$HOME/.agents/providers/claude.md`
- Grok: `$HOME/.agents/providers/grok.md`

Use the current provider's native subagents when delegating to that same
provider. Use a headless CLI invocation only to call a different provider.
Follow the routing guide for context, permissions, and result handling.

## Engineering preferences and feedback

Before implementation or code review, load the applicable sections selected by
`$HOME/.agents/guidelines/README.md`.
When the user asks to extract lessons or preserve a personal rule, load
`$HOME/.agents/guidelines/workflow/learning.md` and
propose the narrowest appropriate location and wording. Do not promote an
unconfirmed inference to a global rule. Include applicable links in agent handoffs.

## Requirements and system analysis

When gathering business requirements or organizing project documentation, load
`$HOME/.agents/guidelines/workflow/business-requirements.md`.
When preparing system analysis, ADR or SPEC, load
`$HOME/.agents/guidelines/workflow/system-analysis.md`.
